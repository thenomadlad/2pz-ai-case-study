# Bedashing V2 — competition, opportunity areas, grounded explanations

Date: 2026-10-07. Status: implemented, except the AI explanation cache still needs
generating with a key (see `docs/remaining.md`).

## Why

A gap analysis of v1 against the case brief (`docs/remaining.md`) found two required
sections missing outright: **competition**, and **whitespace / GROW-WATCH-SKIP**. It also
found an AI layer the public deploy never showed, because the LLM decision backend was
hidden without a key. Reviewer feedback added one more: tables showed numbers with no
units or meaning. V2 closes those gaps within a 3-day budget.

## Who it serves

The app supports one conversation between three roles (also in `CONTEXT.md`):

- the **portfolio team** (network / real estate / expansion), the primary user, forms
  recommendations;
- the **COO** approves or questions them and owns operations and ROIC;
- the **PE board** has to find them defensible.

The headline is written for the COO. The map, drill-down and scenarios are for the
portfolio team. Explanations read like a board memo: claim, evidence, caveat.

## Decisions

| Decision | Chosen | Rejected | Why |
|---|---|---|---|
| Competitor source | OSM Overpass, pulled once and committed (`scripts/fetch_competitors.py`) | Google Places (paid, key), 2GIS (scraping) | Free and reproducible. Counts are a stated lower bound |
| Competitive set | `shop=beauty` + `shop=hairdresser`, minus gents' salons by tag and by name | Tags only | 215 of 984 results were men's salons tagged plain `hairdresser` |
| "Nearby competitor" | Each competitor counts toward its nearest community within 3 km, rolled up per catchment | Fixed radius per branch | One geography for branches and opportunities, and no new geometry code. The 3 km cutoff keeps 87% of competitors and stops edge communities from absorbing the rest |
| Branch scoring | Four signals on **fixed** scales, equal weights | Min-max within the network (v1) | Min-max plus thresholds is still a ranking: the best branch always scores 1. Fixed scales mean one branch's score never moves because a sibling changed, and a healthy network can have zero SHRINKs |
| Tiers | Absolute: PROTECT ≥ 0.65, SHRINK ≤ 0.35 | Forced thirds (v1) | Forced thirds always produces 3 SHRINKs, which is the first thing a reviewer attacks |
| Missing rating | Neutral (0.5), low confidence, caveat | Network median (v1) | Being missing is neither good nor bad, and it should lower confidence |
| Opportunity unit | The 50 seeded communities | H3 hex grid | Reuses trusted population figures, and the names mean something to leadership |
| Opportunity rule | 2×2: nearest branch > 5 km × < 5 competitors per 10k women; ≥ 20k women; worker-housing capped at WATCH | "Underserved if the branch is cannibalised" (backwards); "underserved if the branch is overloaded" (14/50 GROW, because 9 branches give huge straight-line catchments) | Two questions a COO can repeat back |
| Catchments | Straight-line nearest branch (unchanged) | Drive-time matrix | Out of the time budget. Stated, not hidden |
| AI role | Explains decisions; never makes them | An LLM classifier that redoes the rubric (v1, deleted) | Two LLM roles confuse "who decided?", and agreement with a rubric proves nothing |
| AI visibility | Explanations committed in `data/explanations/cache.json`, keyed by a hash of the facts | Calling the API live on the public deploy | Shows AI output without a key and without spending anything per visitor. A stale entry can never be served for changed numbers |

## The explanation layer (`src/explain.py`)

- **Fact sheet** per decision: the table fields plus the signal scores and composite.
- **Glossary**: label, unit and meaning for every field. It drives the tables, the
  evidence lines and the LLM's context.
- **LLM output** (Haiku 4.5, forced tool call): exactly 3 reasons, each with 2–3
  `{field, value}` data points, plus a 2–3 sentence caption for the factor table.
- **`verify`**: every field must exist and its value must match (0.5% tolerance, or
  whole-number rounding). Every number in the prose must match a fact or a published
  threshold. A failure is retried once with the errors fed back, then the template is
  used. The template is grounded by construction (tested).
- **Precedence**: cache hit → live call (only if a key is configured) → template. The
  UI labels which source produced what you're reading.

## What stayed the same

The file-based acquire → features → model pipeline, the in-memory scenario engine and
diff, the self-healing baseline, and the Streamlit app structure. `run_meta.json` now
carries a `pipeline_version`, so an older baseline gets regenerated rather than
crashing the app.

## Known weaknesses

- Equal weights let strong signals hide a fatal one. nad-al-sheba (about 3k women)
  scores HOLD.
- No revenue, rent, capex or lease data, so nothing about return on capital.
- Straight-line catchments and a uniform 49% female share.
