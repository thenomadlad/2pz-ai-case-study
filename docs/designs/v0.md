## Run it

```bash
uv sync --extra dev
just all      # acquire -> features -> model
just serve    # http://localhost:8000
```

No API key or network access required — `MODEL_BACKEND` defaults to `llm`
but auto-falls-back to the deterministic `rubric` backend when
`ANTHROPIC_API_KEY` is unset.

## Real data, and its real limits

- **9 real Dubai branches**, sourced from 2GIS's UAE branch-aggregation page
  (ratings/reviews) plus site verification (areas, head-office exclusion).
  This is the true count, not a research shortfall — Bedashing has 23
  branches UAE-wide and the rest are outside Dubai.
- **50 real Dubai communities**, population figures from the DSC 2022/2024
  Population Bulletin (via a Wikipedia mirror, since `dubaipulse.gov.ae` is
  unreachable — see below).
- **Branch prices: genuinely unavailable, not just hard to fetch.** Checked
  three times across the build (plain HTTP, then a Groupon/Cobone/social
  sweep, then a real-browser Playwright pass on Fresha's actual rendered
  pages). Conclusion: Bedashing has no partnered listing on Fresha anywhere
  — the pages that exist are unclaimed "discovery" pages with service
  *names* and zero prices. No per-branch price exists at any source checked.
  All 9 branches carry the documented fallback constant (`FALLBACK_PRICE_AED
  = 99.0`, the one real Bedashing price point found anywhere — a "Blow Dry
  for AED 99" promotional listing, chain-wide not branch-specific), and are
  correctly flagged as estimated.
- **Community gender split: unavailable for a structural reason, not a
  network fluke.** `dubaipulse.gov.ae` and `dsc.gov.ae` both block automated
  access (Akamai/Imperva WAF), confirmed with a real browser, not just
  `curl`. More importantly: the actual DSC Population Bulletin PDF (recovered
  via the Wayback Machine to check) **does not publish a per-community
  gender split at all** — only emirate-wide. That granularity may exist
  behind DSC's paid/registered API, not available here. All 50 communities'
  female population is estimated via a global share (49%) and flagged as
  such.

Net effect: every `avg_price_aed` and every `population_female` in this
dataset is an estimate, not a reported figure. The pipeline flags both
(`estimated_fields` on each branch, `is_estimated` on each community) and
the frontend renders estimated values with a `~` prefix — this is the
project's own "do not silently impute" principle holding up under its own
worst case.

## Architecture (current state)

Four-stage file-based pipeline, no database:

```
data/seed/*.csv -> acquire -> data/raw/*.json -> features -> data/processed/*.json -> model -> decisions.json
                                                                                            |
                                                                                            v
                                                                                  serve (FastAPI + Leaflet)
```

- `src/acquire/` — seed-first loaders (`branches.py`, `population.py`,
  `prices.py`), each with a stubbed live-fetch path that always falls back
  to seed with a loud warning (live scraping/API integration intentionally
  out of scope for V0 — see the plan's "Scope decisions" section).
- `src/features/` — pure haversine nearest-branch assignment
  (`assign.py`) and per-branch feature rollup with network percentiles
  (`build.py`).
- `src/model/` — `DecisionModel` protocol (`base.py`) with two
  implementations: deterministic `rubric.py` (the zero-API-key guaranteed
  path) and `llm.py` (Anthropic tool-use, disk-cached, falls back to a
  rubric decision — marked `confidence="low"` with a caveat, never cached —
  if the API call fails). `run.py` picks the backend and records which one
  *actually* ran in `run_meta.json`, so the UI's provenance header can't lie
  about it.
- `src/serve/` — FastAPI JSON API + a vanilla-JS/Leaflet frontend, no build
  step. All LLM-originated text is HTML-escaped before rendering.
- Task runner: `justfile` (`just all` / `serve` / `clean` / `test`) —
  swapped from the original `Makefile` partway through (commit `ff51bc1`),
  functionally identical.

## What's known-wrong (by design, not oversight)

See design doc §9 for the full list (nearest-branch assignment ignores
travel time/habit/brand, no competitor data, female population alone is a
poor demand proxy, no revenue/footfall/staffing, LLM labels have no ground
truth, Dubai only). The two items above — zero real prices, zero real
gender splits — are the sharpest version of "prices are a thin basket" and
"female population is a poor demand proxy" that design doc anticipated in
the abstract; this checkpoint is where they turned out to be totally true
rather than partially true.
